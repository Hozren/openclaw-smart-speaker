# Музыка на колонке

## Установка или обновление
1. Определи пользователя аудиосервера и каталог skills, видимый именно голосовому агенту. Прочитай scripts/install.py и запусти от этого пользователя: `python3 scripts/install.py --skill-dir /ABSOLUTE/AGENT/SKILLS/speaker-music`. Установщик скачивает latest опубликованный GitHub release Hozren/openclaw-smart-speaker, проверяет SHA256, устанавливает его CLI и skill, yt-dlp в venv, а отсутствующие mpv/ffmpeg через apt. Python 3.12+ и python3-venv нужны заранее; на другой Linux установи зависимости штатным пакетным менеджером. Не подменяй latest веткой main при отсутствии release.
2. Проверь поддерживаемый JS runtime по документации yt-dlp; CLI использует установленный Deno или Node. Проверь доступ к YouTube реальным поиском; при блокировке сообщи ошибку, не обещай работу и не извлекай cookies без отдельного поручения.
3. Зафиксируй один абсолютный MUSIC_CACHE для всех вызовов (default ~/.cache/openclaw-music). Выбери MUSIC_AUDIO_DEVICE из `mpv --audio-device=help` на том же выходе, что TTS; значение mpv, не просто PipeWire node.name. Выполняй CLI в окружении владельца аудио с корректным XDG_RUNTIME_DIR. Не запускай проигрыватель от root.
4. Зарегистрируй skill для голосового агента штатным механизмом текущей версии OpenClaw; если у агента есть allowlist skills, добавь speaker-music, сохранив остальные настройки. Проверь видимость в новой сессии. Выполни один онлайн-запрос, затем повтор с cached=true, stop и status; получи подтверждение слышимости. Отдельно проверь команды голосом. Наличие файлов не означает готовую интеграцию.

## Воспроизведение
1. Из речи выдели композицию и исполнителя. Передай устойчивый запрос «Исполнитель - Название», без «включи», приветствий и имени колонки. При реальной неоднозначности уточни; не исправляй уверенно неизвестное название на выдуманное. CLI не содержит ИИ и берёт первый результат поиска.
2. Вызови `~/.local/bin/speaker-music play 'Исполнитель - Название'`. Передавай query одним argv-аргументом; при shell используй надёжное экранирование, не вставляй речь в команду. Кэш проверяется до сетевого запроса, неполные файлы не используются. При промахе файл полностью скачивается и сразу включается; это не потоковое воспроизведение во время скачивания.
3. Только после JSON status=playing кратко подтверди запуск. cached показывает попадание в кэш, title — найденную запись. Ошибку загрузки/звука сообщи как ошибку, а не как выполненную команду. Вызов возвращается после начала воспроизведения, а не конца трека. Новый play заменяет старый трек.
4. «Останови музыку» означает обратимую паузу: `speaker-music pause`; «продолжи музыку» — `speaker-music resume`; «отмени музыку» — `speaker-music stop`. Для проверки — `speaker-music status` (различает paused/playing/idle). Корневой слушатель перехватывает точные команды до ИИ, без имени активации. Не отправляй их повторно агенту. При использовании только музыкального skill CLI остаётся доступен агенту. Обработка идёт только через приватный mpv-сокет.
5. Вместе с корневым skill используй один XDG_RUNTIME_DIR: состояние music.json публикуется в speaker-operations. Полный контракт — references/operations.md корневого skill. Не создавай исполняемые команды в файлах операций.

## Границы
Кэш общий только при одинаковом MUSIC_CACHE и пользователе; регистр, Unicode и пробелы нормализуются, но синонимы и другой порядок слов — разные запросы. Файлы не удаляются автоматически. Нет очереди, ducking и эхоподавления. Музыка на открытых динамиках может мешать распознаванию; не заявляй голосовое прерывание проверенным без живого теста. Не обновляй CLI и yt-dlp на каждом play: только при установке/обновлении. После рестарта Gateway дочерний mpv может быть остановлен его cgroup; музыку автоматически не возобновляй.
