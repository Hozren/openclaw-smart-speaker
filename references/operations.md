# Детерминированное управление воспроизведением

## Контракт

Корневой skill включает scripts/operations.py (диспетчер и CLI), scripts/voice_turn.py (фоновая генерация/плеер), scripts/fast_controls.py (потоковое распознавание) и обновлённый speaker.py. Копировать все Python-файлы из scripts, включая local_tts.py, вместе. Таймеров и произвольных задач нет: сейчас поддержаны ровно одна речь и один музыкальный плеер.

Микрофон непрерывно захватывается отдельным потоком. Vosk в потоке захвата проверяет частичные гипотезы по фиксированной грамматике команд. Whisper обрабатывает только фразы, которые не перехватил быстрый канал; его локальный разбор остаётся запасным. Оба разбора предшествуют wake/follow-up/агенту. Имя для управления не нужно, но допускается в начале. Обработка ответа и mpv вынесены в отдельный поток. Новые вопросы во время незавершённого ответа не ставятся в очередь; команды управления принимаются. Окно продолжения 15 секунд отсчитывается после успешного завершения речи.

Фразы целиком (регистр/пунктуация не важны):
- «стоп», «пауза», «останови», «приостанови», «замолчи», «молчи», «хватит» → pause.
- «продолжи», «продолжим» (наблюдаемый вариант ASR), «продолжай», «возобнови» → resume.
- «отмени», «отмена» → stop, окончательное прекращение воспроизведения.
- После глагола: «музыку», «музыка», «воспроизведение» адресуют музыку; «речь», «ответ», «озвучку» адресуют речь. Пример: «продолжи музыку».
- «скажи слово стоп» и «продолжи рассказ» не являются локальными командами.

Без адреса pause/stop выбирает работающую речь, иначе работающую музыку. Уже приостановленная речь не мешает следующему «стоп» поставить музыку на паузу. Resume выбирает последнее приостановленное воспроизведение. Пустой результат no_target не отправляется агенту и не запускает подтверждающую озвучку.

Pause сохраняет точную позицию mpv; resume продолжает её (не начало предложения). Во время генерации pause удерживает готовый ответ до resume; stop подавляет его озвучку. Запрос к удалённому агенту/его инструменты при этом НЕ отменяются. Загрузка песни yt-dlp также не отменяется: управление относится к плееру, не к будущему результату загрузки. Это явные границы протокола v1.

## Состояние и обработчики

Каталог $XDG_RUNTIME_DIR/speaker-operations, либо /tmp/openclaw-music-UID/speaker-operations при отсутствии runtime. Один пользователь и одинаковый XDG_RUNTIME_DIR обязательны для слушателя, CLI и агента. Режим каталога 0700, файлов 0600. Поддерживаемая платформа Linux.

speech.json и music.json — атомарные снимки протокола v1:
- version, id, kind, handler, actions;
- state: running, paused, stopped, finished;
- updated: monotonic clock (для выбора последней паузы);
- речь: phase generating/playing, owner_pid и owner_stamp для проверки живого владельца.

Файлы НЕ содержат команд, текстов ответов, путей произвольных скриптов или секретов. Редактирование JSON не является поддерживаемым способом управления. Детерминированные обработчики — установленный operations.py и voice_turn.py; расширение типов требует изменения allowlist в коде и тестов. Пока адресность — speech/music, не несколько экземпляров одного типа.

Изменения сериализуются flock; уведомления плееру — по его приватному Unix-сокету mpv. speech.sock находится в каталоге операций; музыка использует $XDG_RUNTIME_DIR/speaker-music/mpv.sock. Команды mpv подтверждаются, pause дополнительно читается обратно. Диспетчер не сигналит чужие PID и не исполняет содержимое записей. Состояние музыки обновляется из реального mpv при обращении, окончание трека не требует фонового watcher. После рестарта слушателя старая речь помечается finished; resume не воскрешает удалённые аудиофайлы. Не поднимай второй слушатель.

CLI без ASR и агента:

```sh
python /APP/scripts/operations.py status
python /APP/scripts/operations.py pause
python /APP/scripts/operations.py resume music
python /APP/scripts/operations.py stop speech
python /APP/scripts/operations.py text 'Луна, останови музыку'
speaker-music pause
speaker-music resume
speaker-music stop
```

CLI stop означает окончательный stop; разговорное «стоп» намеренно означает обратимую паузу. Прямой speaker-music stop тоже окончателен.

## Развёртывание и приёмка

Сохрани работающие файлы и unit/env; установи operations.py, voice_turn.py, fast_controls.py и обновлённый speaker.py рядом с local_tts.py. Сохрани VOICE_* и выбранный голос. Обнови музыкальный CLI вместе с его skill; установка standalone music остаётся возможной, отдельный демон диспетчера не нужен. Он запускается как часть существующего voice-сервиса, поэтому наследует его boot-поведение; это не подтверждает готовность headless audio.

Прогони unittest discover -s tests -v. Интеграционный тест mpv использует null audio, без динамиков. Проверь голосом с выбранным микрофоном: стоп во время длинного ответа → тишина; продолжи → та же запись; стоп во время генерации → поздний ответ не звучит до продолжи; отмени ответ → он не озвучивается; адресная пауза музыки не трогает речь. Проверь приоритет при двух активных плеерах и завершённый трек. Подтверждение пользователем обязательно для живого теста.

Короткие команды теперь обходят Whisper и очередь обычных вопросов. Vosk — потоковое локальное ASR, не LLM и не специальная обученная keyword-модель. Используется полный словарь модели и строгий парсер: узкий словарь принудительно превращал посторонние фразы в команды при проверке и поэтому отклонён.

«Стоп», «пауза», «замолчи», «молчи», «хватит» — зарезервированные быстрые префиксы: устойчивое частичное распознавание может сработать ДО конца фразы. Для адресности говори «останови музыку», а не «стоп музыку»: невозможно мгновенно выполнить первое слово и одновременно знать будущий адрес. Остальные глаголы ждут адрес либо короткую тишину; «продолжи рассказ» не должен ошибочно возобновлять музыку. Устойчивость partial — 90 мс; ожидание тишины для безадресных не-eager команд — 450 мс. Один триггер на фразу, затем она исключается из Whisper, чтобы повторный «стоп» не поставил на паузу другую операцию. Свежий recognizer на фразу с общей загруженной моделью исключает наблюдавшийся перенос адаптации между короткими командами.

Очередь обычных запросов ограничена двумя фразами, но быстрый контроль не зависит от этой очереди. Эхоподавления нет — использовать гарнитуру или внешний AEC; собственный звук может активировать команды. Не обещать нулевую задержку или гарантированное распознавание без живой проверки. Потокового TTS нет.

## Установка быстрого канала

В том же venv установи vosk (проверена 0.3.45, Linux x86-64), выполни pip check. Модель из официального каталога https://alphacephei.com/vosk/models :
https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip
SHA256 проверенного архива: 961d5ff98a17f4aa6de69864d0aa71fa5bac682301d2b5d17a3f24c5c99a46d4.

Проверь хеш, безопасно распакуй в VOICE_ROOT/vosk-model-small-ru-0.22, сохрани лицензию и официальный источник. Модель около 45 МБ в архиве, Apache-2.0 по каталогу; не коммитить веса. Не скачивать в runtime. VOICE_CONTROL_MODEL может указать другой совместимый каталог. При включённом быстром канале отсутствие модели останавливает запуск с ошибкой, а не скрытно возвращает медленный режим. VOICE_FAST_CONTROLS=0 — явный откат к Whisper; не представлять его быстрым.

Для воспроизводимого замера с синтетическим тестовым WAV, без вывода звука и действий:

```sh
python scripts/benchmark_controls.py /path/to/test.wav --expect pause:auto
```

Нужны numpy, webrtcvad, ffmpeg и Vosk. Скрипт подаёт PCM в реальном темпе и показывает задержку от приблизительного конца звука до события. Проверяй stop/pause/resume, адресные команды, обычную речь, один триггер на фразу и работу во время Whisper/ответа. Синтетические результаты не заменяют живой тест с пользователем; замеряй на целевом CPU.
